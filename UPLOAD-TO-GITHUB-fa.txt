شاه‌تونل 4.0.1 — راهنمای جایگزینی سورس در GitHub

این ZIP یک بستهٔ کامل Repository Root است؛ فایل‌های پروژه از همان ریشهٔ مخزن شروع می‌شوند و داخل یک پوشهٔ اضافه قرار نگرفته‌اند.

1) مخزن ShahNetLab/ShahTunnel را روی شاخهٔ main باز کنید.
2) ZIP را روی رایانه استخراج کنید.
3) فایل‌ها و پوشه‌های استخراج‌شده را در ریشهٔ مخزن جایگزین نسخهٔ فعلی کنید؛ پوشهٔ S1T-CAPSULE و docs را هم حفظ کنید.
4) تغییرات را در شاخهٔ main ثبت و Push کنید. خود فایل ZIP را به‌عنوان یک فایل داخل مخزن آپلود نکنید.

در گزینهٔ ۹، مسیر Agent→Hub ابتدا با TCP و زمان اتصال تست می‌شود؛ چهار انتقال داخلی روی مسیر سالم اجرا می‌شوند و هنگام شکست مسیر، مسیر بعدی امتحان می‌شود. خروجی کاربران Xray جداگانه با Xray leastPing بین Psiphon و WARP Local Proxy انتخاب می‌شود؛ Direct عمداً خروجی کاربر نیست تا IP عمومی VPS نشت نکند. گزینهٔ ۹ حداکثر ۴ Lane و Psiphon خالص ۳ Lane دارد.

در منوی ساخت Agent، در بخش EXTERNAL EGRESS PROVIDER دو مسیر باقی می‌مانند: `1) Cloudflare WARP over MASQUE` و `2) Psiphon ConsoleClient via local SOCKS5`. گزینهٔ جداگانهٔ `[9] WARP egress` از منوی اصلی مدیریت حذف شده است؛ انتخاب WARP هنگام ساخت Agent، Sidecar و DNS اختصاصی همان پروفایل را خودکار آماده می‌کند. برای خروجی مجزای هر پروفایل، Cloudflare باید در حالت MASQUE و WarpProxy / Local Proxy باشد؛ حالت System Tunnel رد می‌شود چون مسیر آن در سطح کل میزبان است.

پس از انتشار سورس، روی Agent خارج از ایران نصب/ارتقا را اجرا کنید:

bash <(curl -fsSL https://raw.githubusercontent.com/ShahNetLab/ShahTunnel/main/S1T-START.sh)

برای ساخت Agent جدید، در ویزارد ایجاد تونل خروجی WARP/MASQUE یا Psiphon/SOCKS5 را انتخاب کنید. برنامه پیش از شروع سرویس، Xray sidecar اختصاصی همان پروفایل را خودکار می‌سازد و ترافیک TCP/DNS کاربران را از خروجی انتخاب‌شده عبور می‌دهد. گزینهٔ جداگانهٔ WARP در منوی اصلی وجود ندارد. پروفایل‌های موجودِ گزینهٔ ۹ که Sidecar قبلی Psiphon دارند، هنگام اجرای نسخهٔ جدید به‌صورت امن به خروجی تطبیقی مهاجرت می‌کنند؛ پورت‌های Loopback حفظ می‌شوند و در صورت ردشدن تنظیم توسط Xray، فایل قبلی بازیابی می‌شود. Agentهای گزینهٔ ۹ بدون Sidecar قبلی و سایر گزینه‌ها به‌صورت خودکار تغییر نمی‌کنند.

اگر پروفایل Agent قدیمی از مسیر خروجی حذف‌شده استفاده می‌کرد، نسخهٔ جدید آن را به Direct تبدیل نمی‌کند و شروع آن را رد می‌کند. فقط همان پروفایل Agent را دوباره با MASQUE یا Psiphon بسازید؛ پروفایل Hub ایران را حذف یا تغییر ندهید.

نکات مهم:
- این عملیات X-UI، کانفیگ اصلی Xray، SSH و Route پیش‌فرض سیستم را تغییر نمی‌دهد.
- ترافیک TCP و DNS از Psiphon عبور می‌کند. UDP/QUIC و ICMP روی مسیر SOCKS-only مسدود/غیرفعال‌اند تا UDP به‌صورت مستقیم نشت نکند.
- هنگام ساخت Agent جدید، Sidecar قبل از شروع Agent آماده می‌شود؛ هیچ سرویس SSH یا X-UI نباید restart شود.
- بعد از اتصال VPN روی دستگاه کاربر، IP را بررسی کنید. باید با IP خروجی SOCKS5 سایفون برابر باشد، نه IP عمومی Agent.
- در نسخه 4.0.1 اندازه‌گیری RTT داخلی هر ۵ ثانیه تازه می‌شود و نمونه‌های قدیمی‌تر از ۱۵ ثانیه از رتبه‌بندی کنار می‌روند. روی Agent دارای حداقل ۳ GiB RAM، پنجرهٔ کانال SSH سایفون از مقدار پیش‌فرض ۴ به ۱۶ (۵۱۲ KiB) افزایش می‌یابد؛ روی میزبان کم‌حافظه مقدار ۴ حفظ می‌شود. محدودیت‌های Meek/Relay و Threadهای CPU نیز متناسب با RAM/CPU تنظیم می‌شوند و اندازهٔ پیش‌فرض Tunnel Pool تغییر نمی‌کند. این تغییرها توان TCP و انتخاب Lane را بهینه می‌کنند، اما کاهش پینگ فیزیکی یا زمان اتصال انتهابه‌انتهای برنامه را تضمین نمی‌کنند. مسیر SOCKS5 فقط TCP/DNS دارد؛ UDP/QUIC و ICMP پشتیبانی نمی‌شوند.
