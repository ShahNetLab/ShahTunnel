اصلاح دانلود Go برای ShahTunnel

نسخه هدف: Go 1.26.1

نصب‌کننده دانلود Go را بین منابع مختلف ادامه می‌دهد و در صورت پشتیبانی سرور از HTTP Range، دانلود ناقص را از همان نقطه ادامه می‌دهد. زمان کل دانلود محدود به 45 ثانیه نیست؛ اتصال بسیار کند پس از 180 ثانیه بدون پیشرفت متوقف می‌شود. بررسی SHA-256 رسمی برای معماری amd64 و arm64 همچنان اجباری است.

برای اجرای دستور از مخزن، فایل S1T-START.sh باید در مخزن GitHub جایگزین شود؛ دانلود ZIP به‌تنهایی فایل مخزن را تغییر نمی‌دهد.

اصلاح تکمیلی: تابع curl_download_resumable پیش از استفاده تعریف شده است. فایل ناقص برای هر آینه جداگانه نگهداری می‌شود؛ ادامهٔ دانلود فقط از همان میزبان انجام می‌شود تا پاسخ چند میزبان با هم مخلوط نشود. نسخه‌های README و اسکریپت بررسی نیز به Go 1.26.1 یکسان شده‌اند. فایل Go فقط پس از تأیید SHA-256 پذیرفته می‌شود.

نسخه برنامه شاه تونل در این بسته: 2.2.2. از این نسخه، هر تانل با نام و سرویس مستقل ذخیره می‌شود؛ در منوی اصلی مدیریت برنامه (نه منوی پروتکل هنگام ساخت تانل)، برای حذف فقط یک تانل از گزینه 7 و برای حذف کامل برنامه از گزینه 8 استفاده کنید.

در نسخهٔ 2.2.2، گزینهٔ ۷ منوی انتقال همان FULL ADAPTIVE قدیمی و محدود به چهار انتقال داخلی است؛ گزینهٔ ۸ برای یک مسیر جدید Agent (MASQUE/WARP/Tor/Psiphon/Backhaul) و گزینهٔ ۹ برای تقسیم Laneها میان تمام انتقال‌های قدیمی و مسیرهای جدید پیکربندی‌شده است. با تعداد Lane کافی، مسیرهای سالم هم‌زمان فعال می‌مانند و هر Lane هنگام خرابی مسیر خود به گزینه‌های بعدی Failover می‌کند. نصب‌کنندهٔ اصلی روی Ubuntu/Debian کلاینت رسمی Cloudflare WARP را خودکار نصب می‌کند، MASQUE و Local Proxy را تنظیم می‌کند و پس از تأیید صریح شرایط Cloudflare ثبت‌نام/اتصال را انجام می‌دهد. WARP در حالت MASQUE Local Proxy روی SOCKS5 محلی `127.0.0.1:40000` اجرا می‌شود؛ مسیر پیش‌فرض سیستم تغییر نمی‌کند و SSH و ترافیک Xray/VLESS از WARP عبور نمی‌کنند مگر آنکه خودشان صریحاً از پراکسی استفاده کنند.


اصلاح نصب‌کننده 2.2.2 (Hotfix):
- مشکل بازنویسی VERSION توسط /etc/os-release اصلاح شد؛ نسخهٔ برنامه دیگر با نسخهٔ Ubuntu جایگزین نمی‌شود.
- اگر دانلود کلید یا مخزن Cloudflare Timeout بدهد، GPG روی فایل ناموجود اجرا نمی‌شود و مرحلهٔ WARP با هشدار رد می‌شود؛ نصب اصلی Shah Tunnel ادامه می‌یابد. در این حالت مسیر WARP تا نصب موفق کلاینت قابل استفاده نیست.
