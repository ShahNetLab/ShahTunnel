شاه‌تونل 3.0.5
================

- اتصال Psiphon روی پورت عمومی Mapping: وقتی پورت کنترل Hub از مسیر Psiphon مسدود باشد، Agent فقط در مسیر Psiphon به Mapping عمومی پیش‌فرض TCP/443 Hub وصل می‌شود؛ این پورت از پورت کنترل مستقل است. ALPN اختصاصی shah-tunnel-control/1 در همان listener ترافیک کنترل را از TLS کاربران جدا می‌کند و دادهٔ عادی Mapping را بدون تغییر عبور می‌دهد؛ مسیر Direct و پورت کنترل اصلی دست‌نخورده می‌مانند. این قابلیت به Hub نسخه 3.0.3 یا جدیدتر و Agent نسخه 3.0.4 یا جدیدتر نیاز دارد.

- گزینه‌های 1 تا 7 در انتخاب‌گر انتقال همان رفتار و شماره‌گذاری قبلی را حفظ می‌کنند.
- گزینه 8 به انتخاب‌گر انتقال اضافه شده است: Cloudflare WARP با MASQUE (تونل سراسری یا پراکسی محلی WarpProxy)، WARP با WireGuard یا Psiphon از طریق SOCKS5.
- گزینه 9 چهار انتقال داخلی را روی WARP فعال (MASQUE/WireGuard و در MASQUE حالت WarpProxy)، Psiphon و Direct امتحان می‌کند؛ هر مسیر پیش از استفاده راستی‌آزمایی می‌شود و در صورت قطع، مسیر بعدی جایگزین می‌شود. بدون WARP، آخرین مسیر موفق Direct/Psiphon در اولویت است.
- Hub فقط انتقال‌های داخلی را می‌پذیرد؛ انتخاب MASQUE/WARP/Psiphon در نقش Agent انجام می‌شود.
- Psiphon به‌صورت خودکار آماده می‌شود: هنگام ساخت Agent با خروجی Psiphon یا Adaptive، نصب‌کنندهٔ همراه پروژه ConsoleClient رسمی Psiphon را از سورس upstream ثابت‌شده برای معماری amd64/arm64 می‌سازد، نسخه و معماری ELF را بررسی می‌کند و در /usr/local/bin/psiphon-console-client نصب می‌کند. ShahTunnel سپس برای هر Agent فایل JSON خصوصی، دریافت فهرست سرور امضاشده، SOCKS5 یکتای 127.0.0.1 و پوشه داده مستقل تولید می‌کند؛ نیازی به باینری یا JSON دستی نیست. اولین استفاده به دسترسی اینترنت برای دریافت سورس رسمی GitHub و در صورت نیاز Go 1.26.5 از توزیع رسمی Go نیاز دارد. ConsoleClient فقط در حالت local SOCKS اجرا می‌شود؛ هیچ TUN یا مسیر پیش‌فرضی در سیستم ایجاد نمی‌کند. فقط Laneهای TCP ارتباط Agent با Hub از Psiphon استفاده می‌کنند، نه خروجی کاربران Xray. در حالت Adaptive، اگر Psiphon متصل نشود، مسیر Direct باقی می‌ماند. نصب‌کننده مسیر داده را در systemd مجاز می‌کند و ProtectSystem=strict را حفظ می‌کند.
- اصلاح Sandbox در Psiphon: `ListenInterface` خالی می‌ماند تا SOCKS5 روی loopback داخلی Psiphon bind شود؛ اما WebRTC ICE همچنان ممکن است برای کشف رابط‌های شبکه از `AF_NETLINK` استفاده کند. Unit و Drop-in نصب‌کننده این خانوادهٔ سوکت را مجاز می‌کنند و همچنان فقط `CAP_NET_BIND_SERVICE` دارند؛ `CAP_NET_ADMIN` داده نمی‌شود و Route/Interface تغییر نمی‌کند.
- برای WARP/MASQUE وضعیت Connected و پروتکل فعال بررسی می‌شود. هر دو حالت تونل سراسری و Local Proxy پشتیبانی می‌شوند؛ در حالت Local Proxy پورت loopback از warp-cli settings تشخیص داده شده و اتصال TCP هر کانال به Hub از طریق SOCKS5 آن عبور می‌کند. ShahTunnel هرگز route را تغییر نمی‌دهد و WARP را خودکار connect/disconnect نمی‌کند.
- هنگام ساخت Agent با MASQUE، اگر Cloudflare Local Proxy (WarpProxy) از قبل فعال باشد، جداسازی WARP و مسیر DNS به‌صورت خودکار پیش از شروع Agent اعمال می‌شود. برای پروفایل‌های قدیمی، عملیات مدیریت [9] همین کار را انجام می‌دهد. Sidecar مستقل Xray فقط inboundهای همان پروفایل را روی loopback کپی می‌کند؛ تنظیمات و سرویس X-UI تغییر یا restart نمی‌شوند و سایر پروفایل‌ها Direct می‌مانند. DNS نیز با DoH و از همان WARP عبور می‌کند.
- گزینه 8 منوی اصلی مدیریت همچنان حذف کامل نصب است؛ گزینه 8 جدید فقط داخل انتخاب‌گر انتقال کاربرد دارد.
- Network Flow به نسخه 3 به‌روزرسانی شده و مرز لایه انتقال داخلی/مسیر خروجی را مشخص می‌کند.

نکتهٔ SSH:
فعال کردن WARP ممکن است مسیر پیش‌فرض سیستم را تغییر دهد. آن را از کنسول ارائه‌دهنده یا با دسترسی جایگزین آزمایش کنید؛ فقط با یک نشست SSH اقدام به تغییر default route نکنید.

تست‌ها شامل عبور نشست‌های TCP/TLS، WebSocket/TLS، HTTP/2 و HTTP/1.1، پراکسی SOCKS5 و WARP Local Proxy با SOCKS5، failover مسیر خروجی، `go vet` و build برای amd64/arm64 هستند. تست زنده WARP به کلاینت فعال و اینترنت نیاز دارد.

نصب‌کننده سرویس فعال ShahTunnel را خودکار restart نمی‌کند تا نشست‌ها قطع نشوند. پس از آماده‌بودن برای وقفه کوتاه تونل، فقط سرویس مربوط به ShahTunnel را restart کنید؛ sshd دست‌کاری نمی‌شود.

روش انتشار و نصب:
- در GitHub فقط سورس، تست‌ها، مستندات و S1T-START.sh قرار می‌گیرد؛ هیچ باینری ShahTunnel را commit یا در Releases آپلود نکنید.
- دستور one-line بالا اسکریپت را از raw.githubusercontent.com دریافت می‌کند.
- اسکریپت سورس را از codeload.github.com/ShahNetLab/ShahTunnel شاخه main می‌گیرد، ابزار Go نسخه 1.26.1 را از توزیع رسمی Go با SHA-256 معتبر می‌کند و باینری را روی همان VPS می‌سازد.
- باینری نهایی فقط روی VPS در /usr/local/bin/ravanreverse نصب می‌شود.


نصب سریع از GitHub (Linux amd64/arm64 با systemd):
bash <(curl -fsSL https://raw.githubusercontent.com/ShahNetLab/ShahTunnel/main/S1T-START.sh)


## اصلاح اتصال Psiphon در پروفایل موجود

اگر ConsoleClient نصب شده اما پیش از ایجاد تونل خارج می‌شود، پس از اجرای نصب‌کنندهٔ جدید، اسکریپت نصب‌شدهٔ تعمیر را اجرا کنید: `sudo bash /usr/local/lib/shah-tunnel/repair-psiphon-profile.sh s`. این اسکریپت فقط همان Agent را متوقف/اجرا می‌کند، قبل از کار از فایل Psiphon نسخهٔ پشتیبان می‌گیرد و مجوز نوشتن پوشهٔ داده را فقط در صورت نیاز و فقط برای همان پروفایل اضافه می‌کند. باینری جدید هنگام شروع، شناسه‌های placeholder یا خالی و قالب قدیمی تک‌آدرس را تشخیص می‌دهد و کانفیگ را به قالب جدید RemoteServerListURLs و ObfuscatedServerListRootURLs مهاجرت می‌دهد؛ شناسه‌های معتبر سفارشی و منطقهٔ خروجی حفظ می‌شوند. اسکریپت تا ۱۰۰ ثانیه برای آماده‌شدن SOCKS5 محلی صبر می‌کند. اگر SOCKS5 آماده شود ولی تونل واقعی Psiphon یا Lane ارتباط Agent↔Hub هنوز وصل نشده باشد، وضعیت PENDING گزارش می‌شود و سرویس برای ادامهٔ تلاش‌ها روشن می‌ماند؛ موفقیت اتصال ادعا نمی‌شود. فقط اگر SOCKS5 محلی در مهلت تعیین‌شده آماده نشود، همان پروفایل متوقف می‌شود. پیام‌های تشخیصی Psiphon در Journal محلی فعال‌اند و ممکن است جزئیات حساس نشست/شبکه داشته باشند؛ آن‌ها را عمومی منتشر نکنید.

- شروع Psiphon: نسخه 3.0.5 پس از آماده‌شدن SOCKS5 محلی، فرایند ConsoleClient را به‌خاطر مهلت ثابت ۹۰ ثانیه نمی‌کشد. تا زمان اتصال واقعی Psiphon تلاش ادامه پیدا می‌کند؛ ویزارد وضعیت در انتظار را از اتصال موفق جدا نشان می‌دهد. گزارش‌های تشخیصی فقط در Journal محلی ثبت می‌شوند و ممکن است جزئیات شبکه داشته باشند.

- اصلاح نسخه 3.0.5: در حالت Psiphon، TCP/TLS و WebSocket/TLS از Public Mapping استفاده می‌کنند؛ HTTP/2 CONNECT و HTTP/1.1 CONNECT به‌ترتیب از Control Port+1 و Control Port+2 استفاده می‌کنند. آدرس Mapping دیگر مبنای محاسبه پورت‌های CONNECT نیست.

- اصلاح خودکار نسخه 3.0.5: مجوز `AF_NETLINK` در فایل‌های اصلی سرویس و Drop-in نصب‌کننده ثبت شده است تا هنگام نصب و ارتقا دیگر نیازی به ساخت دستی فایل `10-psiphon-netlink.conf` نباشد.
