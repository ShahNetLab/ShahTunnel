Shah Tunnel 2.2.2

تغییرات منوی انتقال:
- گزینه‌های ۱ تا ۶ بدون تغییر در رفتار قبلی حفظ شده‌اند.
- گزینه ۷: FULL ADAPTIVE FAILOVER بین چهار انتقال قدیمی.
- گزینه ۸: انتخاب یک مسیر خارجی؛ MASQUE gateway، Cloudflare WARP، WARP on WARP، Tor یا Psiphon.
- گزینه ۹: ترکیب چهار انتقال قدیمی با مسیرهای خارجی و Failover خودکار هر Lane.

در Wizard مسیر خارجی، انتخاب پیش‌فرض شماره ۲ (Cloudflare WARP) است. گزینه ۱ MASQUE فقط برای Gateway از قبل اجراشده است و قبل از ذخیره، Handshake واقعی SOCKS5 را بررسی می‌کند.

برای اصلاح پروفایل Agent قبلی که اشتباهاً روی MASQUE بدون Gateway ذخیره شده، بعد از نصب نسخه جدید روی سرور خارج اجرا کنید: `ravanreverse repair-external`؛ پروفایل را انتخاب و گزینه ۲ (Cloudflare WARP) را بزنید. فرمان قبل از تغییر پشتیبان می‌گیرد و توکن، Fingerprint، Hub، Mappingها و تعداد Laneها را حفظ می‌کند.

Cloudflare WARP در نصب‌کننده فقط روی Debian/Ubuntu پشتیبانی‌شده نصب می‌شود و هنگام نصب نه ثبت‌نام و نه متصل می‌شود. هنگام انتخاب WARP در Wizard، حالت پراکسی محلی SOCKS5 با MASQUE روی 127.0.0.1:40000 تنظیم و با درخواست واقعی Cloudflare بررسی می‌شود. فقط اتصال‌های Shah Tunnel از این پراکسی عبور می‌کنند؛ مسیر پیش‌فرض سیستم و SSH از WARP عبور داده نمی‌شوند.

MASQUE مستقل و WARP on WARP به یک SOCKS5 gateway ازپیش‌آماده‌شده نیاز دارند. Shah Tunnel کلاینت مستقل MASQUE یا ثبت‌نام دوم Cloudflare را به‌صورت خودکار ایجاد نمی‌کند.

برای اجرای نسخه داخل ZIP، فایل‌ها را استخراج کنید و از پوشه اصلی با دسترسی root اجرا کنید:
  sudo bash S1T-START.sh

دستور زیر فقط پس از انتشار فایل‌های همین نسخه در شاخه main مخزن GitHub، نسخه 2.2.2 را نصب می‌کند:
  bash <(curl -fsSL https://raw.githubusercontent.com/ShahNetLab/ShahTunnel/main/S1T-START.sh)

این ZIP به‌تنهایی فایل‌های مخزن GitHub را تغییر نمی‌دهد.
