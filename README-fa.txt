ShahTunnel 5.5.11 — اصلاح مسیر خروجی کاربران Psiphon

نسخهٔ 5.5.11 پیش از پذیرفتن هر خروجی Psiphon، علاوه بر IP عمومی و DNS، یک اتصال واقعی TLS/ALPN/Token احرازشده از طریق SOCKS5 به آدرس انتقال Hub برقرار می‌کند. اگر Exit پورت Hub را با خطایی مانند SOCKS5 reply=5 رد کند، گزینهٔ بعدی بررسی می‌شود. پورت انتقال سفارشی مانند 2083 بازنویسی نمی‌شود؛ پورت سرویس کاربران و مقصد Xray آن مستقل است و تغییر نمی‌کند.

اصلاحات اصلی:
- مسیر Agent↔Hub هنگام استفاده از Psiphon فقط TCP/TLS و WebSocket/TLS را روی Mapping عمومی Hub امتحان می‌کند؛ پورت‌های HTTP/2 و HTTP/1.1 CONNECT (پورت کنترل +۱ و +۲) از مسیر Psiphon حذف شده‌اند چون خارج از پورت‌های خروجی مجاز هستند.
- نشانی انتقال خصوصی Psiphon به Hub از نظر قالب و بازهٔ پورت اعتبارسنجی می‌شود؛ مقدار سفارشی مانند 2083 حفظ می‌شود و با اتصال واقعی TLS/ALPN/Token از طریق SOCKS5 آزموده می‌شود. Exit ناموفق کنار گذاشته شده و کشور بعدی بررسی می‌شود.
- گزینهٔ ۹ چهار انتقال داخلی و Failover مستقل Direct/Psiphon/MASQUE فعال را برای Laneهای Agent↔Hub حفظ می‌کند.
- پس از فعال‌شدن خروجی کاربران، زمان‌بند مستقل systemd هر یک ساعت مسیر خروجی Psiphon را دوباره بررسی و در صورت امکان جایگزین می‌کند؛ مسیر جدید فقط پس از تأیید IP عمومی پذیرفته می‌شود. هنگام تعویض ممکن است اتصال‌های جاری برای چند ثانیه قطع شوند، اما مسیر مستقیم VPS جایگزین نمی‌شود.
- انتخاب خروجی Psiphon با بررسی مرحله‌ای گزینه‌های معتبر انجام می‌شود. خروجی فقط زمانی پذیرفته می‌شود که IP عمومی آن با IP مستقیم VPS متفاوت باشد؛ در غیر این صورت مسیر کاربران فعال نمی‌شود.
- در گزینهٔ ۹، ترافیک TCP/DNS کاربران Xray نیز از Sidecar اختصاصی همان Agent و SOCKS5 سایفون عبور می‌کند؛ مسیر پیش‌فرض سرور یا SSH تغییر نمی‌کند.
- UDP/QUIC و ICMP از SOCKS5 سایفون پشتیبانی نمی‌شوند؛ UDP در Sidecar مسدود می‌شود تا به‌صورت ناخواسته از IP مستقیم سرور خارج نشود.
- گزینهٔ اختصاصی Psiphon / SOCKS5 نیز همچنان برای خروجی کاربران و Laneهای Agent از Psiphon استفاده می‌کند.
- زمان‌بندی Laneها همچنان از RTT معتبر، تعداد جریان‌های فعال، فشار صف و زمان انتظار نوشتن استفاده می‌کند.
- سرویس Psiphon مستقل از Restart سرویس Agent اجرا می‌شود؛ بنابراین Restart معمولی Agent تونل‌های گرم Psiphon را از بین نمی‌برد.
- هنگام ساخت Agent، Sidecar Xray، خروجی HTTPS و DoH واقعی Psiphon و اتصال احرازشده به Hub پیش از شروع Agent بررسی می‌شوند؛ گزینه‌های خروجی به‌ترتیب بررسی و IP عمومی خروجی با IP مستقیم VPS مقایسه می‌شود.
- IP خروجی SOCKS5 با IP مستقیم VPS مقایسه می‌شود؛ اگر یکسان باشند یا Mapping به Sidecar اختصاصی اشاره نکند، مسیر کاربر fail-closed باقی می‌ماند.
- عملیات Stop سرویس Agent، Sidecar اختصاصی Xray و Psiphon همان پروفایل را متوقف می‌کند؛ Start بعدی آن‌ها را دوباره راه‌اندازی می‌کند.
- گواهی‌ها و کلیدهای TLS واقع در /root و /home در Sidecar به‌صورت فقط‌خواندنی قابل دسترسی هستند.

- Tag داخلی DNS برای هر پروفایل یکتا است و درخواست‌های DoH با نام میزبان از SOCKS5 همان پروفایل عبور می‌کنند؛ هنگام انتخاب خروجی Psiphon، علاوه بر IP عمومی، دریافت پاسخ واقعی DoH از طریق SOCKS5 نیز بررسی می‌شود تا بازبودن صرف پورت SOCKS به‌اشتباه سلامت DNS تلقی نشود. قوانین قدیمی DNS در X-UI نمی‌توانند این مسیر را به Direct منحرف کنند. صفحهٔ وضعیت و گزارش‌ها، Journal سرویس Xray و Psiphon همان پروفایل را نیز نمایش می‌دهد.
- نصب‌کننده فقط Sidecar متعلق به همان پروفایل را درجا اصلاح می‌کند، قبل از تغییر فایل Xray اعتبارسنجی می‌کند و در صورت شکست، نسخهٔ قبلی را بازمی‌گرداند.
- آمادگی Psiphon با سرویس مستقل، Handshake واقعی SOCKS5 و لاگ Lane احراز‌شده سنجیده می‌شود؛ پیام‌های سرویس مستقل Psiphon به اشتباه از Journal سرویس Agent انتظار نمی‌روند.

نصب از مخزن:
روش جایگزین نصب (بدون raw.githubusercontent.com):
set -o pipefail
curl -fsSL --connect-timeout 10 --max-time 30 \
  -H 'Accept: application/vnd.github+json' \
  -H 'User-Agent: ShahTunnel-bootstrap' \
  'https://api.github.com/repos/ShahNetLab/ShahTunnel/contents/S1T-START.sh?ref=main' \
| python3 -c 'import sys,json,base64; d=json.load(sys.stdin); sys.stdout.buffer.write(base64.b64decode(d["content"]))' \
| bash

اعمال اصلاح روی Agent قدیمی با گزینهٔ ۹:
1. نسخهٔ 5.5.11 را روی Hub و Agent نصب/جایگزین کنید.
2. از منوی ShahTunnel همان پروفایل Agent را Start/Restart کنید؛ Sidecar اختصاصی Psiphon پیش از شروع Agent ساخته و مسیر خروجی واقعی بررسی می‌شود. اگر Agent از قبل فعال بوده و Mapping قبلاً اعمال نشده باشد، فقط یک بار برای اعمال مسیر جدید Restart می‌شود.
3. IP را از دستگاه کلاینتی که به کانفیگ Xray وصل است بررسی کنید. اجرای `curl` روی خود VPS یا بررسی سرویس‌های نامرتبط، همچنان IP عادی سرور را نشان می‌دهد؛ Route پیش‌فرض سرور و SSH عمداً تغییر نمی‌کنند.

اگر اجرای قبلی نیمه‌کاره مانده و سرویس اختصاصی Xray/Psiphon از قبل وجود دارد، نسخهٔ 5.5.11 همان سرویس مدیریت‌شدهٔ متعلق به پروفایل را به‌روزرسانی می‌کند؛ سرویس ناشناس یا متعلق به پروفایل دیگر را دست‌کاری نمی‌کند. فایل‌های systemd را دستی حذف نکنید.

نکتهٔ ظرفیت: در گزینهٔ ۹ ترافیک کاربران این پروفایل از ظرفیت خروجی Psiphon عبور می‌کند؛ بنابراین Psiphon می‌تواند در بار هم‌زمان ۱۶ کاربر گلوگاه سرعت باشد. سرعت نهایی به CPU، RAM، ظرفیت شبکهٔ هر دو VPS، کیفیت مسیر و ظرفیت Relayهای Psiphon بستگی دارد. برای ارزیابی واقعی باید پس از نصب، بار و مصرف منابع هر دو سرور اندازه‌گیری شود.


نگهداری پورت Psiphon: پورت صریح Mapping خصوصی Agent به Hub، از جمله 2083، هنگام ذخیره و بارگذاری حفظ می‌شود و ShahTunnel آن را به صورت محلی به 443 بازنویسی نمی‌کند. دسترسی واقعی همچنان به سیاست خروجی Exit انتخاب‌شدهٔ Psiphon بستگی دارد. پورت‌های مقصد Xray کاربران مستقل و دست‌نخورده می‌مانند.


اصلاح پایداری در نسخهٔ 5.5.11:
- مقدار TunnelPoolSize در پروفایل‌های جدید و قدیمی روی 1 تثبیت شد؛ این مقدار، مقدار پیش‌فرض توصیه‌شدهٔ Psiphon است.
- هنگام ارتقای پروفایل، اگر TunnelPoolSize قبلی 2 تا 16 بوده باشد، به 1 تغییر می‌کند و سرویس Psiphon همان پروفایل برای اعمال تنظیم جدید Restart می‌شود.
- پورت عمومی کاربران 2083، تمام پورت‌های صریح دیگر، Mappingها، مقصدهای محلی Xray و اعتبارنامه‌های کاربران تغییر نمی‌کنند.
- این اصلاح از ایجاد چند مسیر مستقل Psiphon با کیفیت نامتوازن جلوگیری می‌کند؛ تأیید اتصال نهایی روی Hub و Agent واقعی همچنان لازم است.
