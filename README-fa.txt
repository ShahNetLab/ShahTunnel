ShahTunnel — تعمیر Tor EXEC FORMAT ERROR
=========================================

علت خطای گزارش‌شده
-------------------
نسخه قبلی ممکن است اولین فایل اجرایی به نام tor را از مسیر debug/tor انتخاب کند.
در Expert Bundle، فایل runtime اصلی باید از tor/tor انتخاب شود. انتخاب فایل داخل
debug یا باینری نامتناسب با معماری سرور باعث خطای exec format error می‌شود.

این بسته چه کار می‌کند؟
-----------------------
1) سورس فعلی شاخه main مخزن ShahNetLab/ShahTunnel را دریافت می‌کند؛ بنابراین سورس
   قدیمی داخل این ZIP جایگزین نسخه فعلی پروژه نمی‌شود.
2) جست‌وجوی Tor را اصلاح می‌کند: مسیر debug نادیده گرفته می‌شود و مسیر runtime
   tor/tor و lyrebird اولویت دارد.
3) فایل‌های اجرایی را از نظر ELF، معماری amd64/arm64 و اجرای واقعی tor --version
   بررسی می‌کند. checksum نسخه رسمی Tor همچنان از مقادیر pin‌شده در سورس حفظ می‌شود.
4) مسیرهای قدیمی ذخیره‌شده در تنظیمات Agent هنگام شروع دوباره resolve می‌شوند؛ لازم
   نیست پروفایل s را حذف یا از اول ایجاد کنی.
5) سورس اصلاح‌شده را با نصب‌کننده اصلی ShahTunnel build/install می‌کند و فقط
   Agentهایی را که underlay آن‌ها tor_socks5 است دوباره راه‌اندازی می‌کند؛ سرویس
   Xray اختصاصی همان پروفایل نیز در صورت وجود restart می‌شود.

نحوه استفاده
------------
الف) فایل S1T-TOR-EXEC-FORMAT-FIX.sh را در ریشه مخزن GitHub، کنار S1T-START.sh
   آپلود کن. فایل‌های قبلی و README نصب آسان را حذف یا جایگزین نکن.

ب) روی VPS به‌صورت root اجرا کن:

bash <(curl -fsSL https://raw.githubusercontent.com/ShahNetLab/ShahTunnel/main/S1T-TOR-EXEC-FORMAT-FIX.sh)

یا اگر مخزن را روی VPS clone کرده‌ای، اسکریپت را در ریشه همان checkout قرار بده و
اجرا کن:

bash S1T-TOR-EXEC-FORMAT-FIX.sh

پس از پایان، وضعیت پروفایل s را بررسی کن:

systemctl status ravanreverse@s.service --no-pager
journalctl -u ravanreverse@s.service -n 100 --no-pager

در لاگ باید Bootstrap موفق Tor (عبارت Bootstrapped 100%) و اتصال Laneهای Hub دیده
شود. صرف active بودن systemd به‌تنهایی معیار سلامت انتها‌به‌انتها نیست.

محدودیت‌ها و نکات ایمنی
----------------------
- مخزن GitHub باید برای دریافت codeload/raw عمومی و قابل دسترس باشد؛ در غیر این صورت
  اسکریپت قبل از تغییر فایل‌های نصب‌شده متوقف می‌شود. راه جایگزین، اجرای اسکریپت از
  داخل checkout محلی سورس است.
- اگر ساختار سورس فعلی با الگوهای مورد انتظار فرق کرده باشد، اسکریپت متوقف می‌شود و
  تغییر ناقص را build/install نمی‌کند.
- فایل‌های تنظیمات پروفایل موجود حذف نمی‌شوند.
- اسکریپت مسیرهای SSH، جدول route، فایروال و کانفیگ اصلی X-UI را تغییر نمی‌دهد.
- مسیر Tor-only فعلی TCP/DNS است؛ UDP، QUIC و ICMP همچنان روی این مسیر مسدود می‌مانند.

تست‌های انجام‌شده در محیط ساخت
-------------------------------
- bash -n برای اسکریپت تعمیر و نصب‌کننده Tor
- gofmt و go test ./... روی checkout آزمایشی موجود
- ساخت Linux/amd64 و Linux/arm64 و بررسی نوع ELF خروجی

این تست‌ها اجرای زنده روی VPS تو یا Bootstrap واقعی Tor را تأیید نمی‌کنند؛ نتیجه نهایی
باید از journal سرویس روی همان VPS بررسی شود.
