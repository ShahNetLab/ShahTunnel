## معماری کهکشانی شاه‌تونل

شاه‌تونل مثل یک شبکهٔ مداری طراحی شده است: **Hub** نقطهٔ ورود عمومی و مرکز هماهنگی است؛ هر **Agent** اتصال‌های خروجی احرازشده و مستقل را به Hub برقرار می‌کند و ترافیک را به سرویس محلی متناظر می‌رساند. هر مسیر مانند یک مدار مستقل عمل می‌کند؛ اختلال یک Lane نباید مسیرهای سالم یا پروفایل‌های دیگر را از کار بیندازد.

### توانایی‌های اصلی

- **چهار انتقال داخلی:** TCP/TLS، ‏WebSocket/TLS، ‏HTTP/2 CONNECT و ‏HTTP/1.1 CONNECT/TLS.
- **انتقال تطبیقی:** بازیابی مستقل Laneها و تغییر مسیر انتقال بدون تغییر هویت و کانال احرازشدهٔ Hub و Agent.
- **خروجی Agent:** مسیر مستقیم، Cloudflare WARP با MASQUE یا WireGuard و Psiphon از طریق SOCKS5 محلی.
- **WARP اختصاصی هر تانل Xray:** ساخت یک Sidecar جداگانه که فقط Inbound انتخاب‌شده را روی Loopback کپی می‌کند و از WARP SOCKS5 عبور می‌دهد.
- **DNS خودکار در مسیر WARP:** درخواست‌های DNS کاربران در Sidecar دریافت می‌شوند، از DoH کلادفلر/گوگل استفاده می‌کنند و درخواست Resolver نیز از همان خروجی WARP عبور می‌کند.
- **جداسازی پروفایل‌ها:** هر تانل تنظیمات و سرویس systemd مستقل دارد؛ Inboundهای دیگر Xray و پروفایل‌های دیگر بدون تغییر باقی می‌مانند.

### WARP اختصاصی، بدون تغییر مسیر کل سرور

هنگام ساخت Agent با انتقال MASQUE، اگر Cloudflare Local Proxy یا همان `WarpProxy` از قبل فعال باشد، شاه‌تونل به‌صورت خودکار Sidecar اختصاصی Xray و مسیر DNS را آماده می‌کند و سپس Agent را بالا می‌آورد. نیازی به ویرایش دستی JSON یا اجرای دستور اصلاحی روی سرور نیست. برای Agentهای موجود، از مسیر **Manager → [9] WARP egress** استفاده کنید.

فقط Inbound کپی‌شدهٔ همان پروفایل از SOCKS5 محلی WARP عبور می‌کند. فایل تنظیمات و سرویس Xray تحت مدیریت X-UI تغییر یا Restart نمی‌شوند. Inboundهای دیگر، از جمله پروفایل‌هایی که Direct می‌مانند، جابه‌جا نمی‌شوند. شاه‌تونل در قابلیت WARP اختصاصی، Default Route سرور را تغییر نمی‌دهد، SSH را Restart نمی‌کند و WARP را روشن یا خاموش نمی‌کند. اگر Local Proxy فعال نباشد، برنامه به‌صورت پنهانی سراغ مسیریابی سراسری نمی‌رود.

### امنیت و پایداری

- TLS 1.3، احراز هویت Token و تثبیت اثرانگشت SHA-256 برای ارتباط Hub و Agent.
- پروفایل‌ها و سرویس‌های مستقل systemd.
- Sidecarهای Xray محدود به Loopback برای پروفایل‌های انتخاب‌شدهٔ WARP.
- محدودماندن اختلال در همان Lane یا پروفایل؛ قابلیت WARP اختصاصی مسیر عمومی سرور را دست‌کاری نمی‌کند.

## نصب

روی سرور Linux پشتیبانی‌شده (amd64 یا arm64) دارای systemd و با دسترسی root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ShahNetLab/ShahTunnel/main/S1T-START.sh)
```

نصب‌کننده سورس پروژه را دریافت و باینری ShahTunnel را روی همان سرور Build می‌کند؛ نیازی به باینری ازپیش‌ساخته‌شده داخل مخزن نیست.

## بررسی انتقال‌ها

از پوشهٔ سورس اجرا کنید:

```bash
./VERIFY-ALL-TRANSPORTS.sh
```
